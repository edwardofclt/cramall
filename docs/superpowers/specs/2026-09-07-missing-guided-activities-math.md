## M1 — Estimate Checkpoint

**Placement:** `math-u02-l02-c3` in `math-u02-l02`, *Estimate and Judge Reasonableness*. Standard: `4.NR.1.2`.

**Concept → action → result → reasoning:** Choose useful rounded quantities; place numbers at rounded checkpoints and build an estimate equation; compare the estimate with a proposed solution; explain whether its size makes sense.

**Practice setup:** Two acorn counts are 36,418 and 22,693. A sign claims their sum is 159,111. The learner chooses rounding to the nearest thousand or ten thousand, places each count on a labeled number line, and chooses its rounded endpoint. The exact sum is concealed during estimation.

**Loop:** Predict whether the claim is plausible → commit rounded endpoints and assemble the addition equation → submit to reveal an estimate marker beside the claim → explain that the claim is far larger than either supported estimate. Optional second round: a difference claim of 45,842 for 72,381 − 26,539, checked using nearest-thousand rounding. The work surface retains both original quantities, chosen rounding place, equation, and claim; it does not use an arbitrary “close enough” percentage.

**Dialogue:** Nutty: “This acorn sign might have a counting mistake. Choose friendly numbers to check its size.” Kid: “I’ll round both counts, build an estimate, and compare it with the sign.” Start: **Check the sign**.

**Coaching:** On a committed rounding mistake: “Look at the digit just to the right of your rounding place.” After a valid estimate: “Keep your estimate beside the claim. Compare their sizes.” On an unsupported verdict: “Does that claimed total fit the two amounts you started with?” On completion: “You used an estimate to catch a result with the wrong size.”

**Finish/key:** Primary: 36,000 + 23,000 = 59,000 or 40,000 + 20,000 = 60,000; reject 159,111. Reveal exact 59,111 only after the verdict. Optional difference estimate: 72,000 − 27,000 = 45,000; 45,842 is plausible. Require correct rounding, a valid equation, and a supported verdict; a changed rounding choice resets the verdict check.

**Build/verify:** New estimation mode/component; reuse number-line visual/control patterns, not its two-number comparison task unchanged. Test both valid rounding strategies and hidden exact answers.

## M2 — Acorn Rule Machine

**Placement:** `math-u03-l02-c2` in `math-u03-l02`, *Rules and Function-Table Patterns*. Standard: `4.PAFR.3.2`.

**Concept → action → result → reasoning:** One rule must fit every input-output pair; insert operation tiles and test inputs; retain each proposed output alongside known outputs; explain why one matching row is insufficient.

**Practice setup:** Bags of seeds: input 2 bags gives 12 seeds, 4 gives 24, 7 gives 42. Candidate rules are ×6, +10, and ×4. The table also has input 5 with unknown output, and unknown input with output 54. Units stay attached to headings.

**Loop:** Choose a rule → send the three known input cards through the machine → inspect every retained comparison → revise if needed → fill the two missing entries → use the rows to explain the rule. The +10 rule deliberately fits the first row, so testing all rows matters. A grouping picture shows equal bags, not just a spinning machine.

**Dialogue:** Nutty: “A seed machine follows one rule every time. One matching row might fool us.” Kid: “I’ll test my rule on every row, then fill the missing spaces.” Start: **Test a rule**.

**Coaching:** First full test: “Compare each predicted output with its recorded output.” Wrong rule: “That rule fits one row but changes the pattern in another. Try a rule that fits all three.” Valid rows: “Now use the same rule in both directions.” Completion: “You checked a rule across the table and used it to extend the pattern.”

**Finish/key:** ×6; 5 → 30; 9 → 54. Require testing all three known rows, filling both unknowns, and choosing the explanation “Each bag adds the same six seeds.” No completion on a single test or a correct guessed rule alone.

**Build/verify:** New function-table activity; reuse array/group illustrations. Test first-row false confidence, inverse input solving, and resetting comparisons when the rule changes.

## M3 — Pack, Use, Rebuild

**Placement:** `math-u05-l02-c2` in `math-u05-l02`, *Two-Step Equations with an Unknown*. Standard: `4.PAFR.3.4`.

**Concept → action → result → reasoning:** Represent a two-step story with an unknown; construct operation order and grouped quantities; observe the intermediate and final amounts; check an unknown in a second position.

**Practice setup:** Four packs hold 18 markers each; 15 markers are used. How many remain? The mat has four empty pack outlines, marker bundles, a used-marker tray, operation tiles, parentheses, and `m`. A second short round says: “Some packs hold 18 markers each. After 15 markers are used, 57 remain. How many packs were there?”

**Loop:** Build the pack groups → assemble `m = (4 × 18) − 15` before revealing a calculated total → run the two stages and enter intermediate/final values → rebuild the inverse story with `(p × 18) − 15 = 57` → restore used markers and regroup to find the pack count. Each pack can be moved with select/place buttons; 72 tiny independent taps are never required.

**Dialogue:** Nutty: “Some markers were packed, then some were used. Our model needs both events in order.” Kid: “I’ll build the packs, show what was used, and check where the unknown belongs.” Start: **Build the marker story**.

**Coaching:** Wrong order: “Which amount must exist before we can remove used markers?” After the intermediate result: “Keep that total. It becomes the starting amount for the next step.” Inverse mistake: “Rebuild the amount before any markers were used.” Completion: “Your equations match both stories, even when the unknown moves.”

**Finish/key:** 72 total, 57 remain, inverse answer 4 packs. Require both equation constructions and checks. Equivalent properly grouped forms are accepted; do not require one visual tile ordering for commutative multiplication.

**Build/verify:** New two-step story builder. Existing balance/array components supply visual ideas, not complete two-step semantics. Test unknown placement, operation order, units, and meaningful inverse recovery.

## M4 — Fraction Picnic

**Placement:** `math-u06-l02-c3` in `math-u06-l02`, *Compose and Decompose Like-Denominator Fractions*. Standard: `4.NR.2.4`.

**Concept → action → result → reasoning:** Repartition one quantity without changing piece size or total; move eighth-size pieces between plates; retain two different decompositions; explain why the denominator stays eight.

**Practice setup:** Eleven eighth-size sandwich pieces on two equal-size whole outlines. Each whole has exactly eight slots. Three labeled plates allow grouping, with count badges and large add/remove controls.

**Loop:** Predict whether eleven eighths will fill more than one whole → distribute all pieces into two nonempty groups → commit a sum → make a different two- or three-group decomposition → compare both sums with the same filled whole outlines and number-line point. Each plate uses a distinct pattern/label so decomposition is visible without relying on color. Piece movement conserves quantity.

**Dialogue:** Nutty: “These sandwich pieces are all the same size. Can we share them in different groups without changing how much food there is?” Kid: “I’ll move the eighths, record two groupings, and compare their totals.” Start: **Arrange the picnic**.

**Coaching:** Wrong denominator: “Moving a piece did not cut it into a new size.” First valid grouping: “Keep that record. Find another grouping with the same total.” Duplicate grouping: “Changing the order repeats the same groups. Try changing how many eighths are on a plate.” Completion: “Your two sums describe the same eleven eighth-size pieces.”

**Finish/key:** Any two distinct unordered nonempty partitions of 11, each with denominator 8; e.g. 5/8 + 6/8 and 8/8 + 3/8. Explain same-sized parts and conserved count; connect to 1 3/8 without making conversion the main task. Accept valid three-group sums.

**Build/verify:** Extend fraction models with explicit decomposition/group records and multiwhole targets; current target validation must be updated deliberately for this mode. Test conservation, multiple answers, and reordered duplicates.

## M5 — Bundle the Fourths

**Placement:** `math-u06-l03-c2` in `math-u06-l03`, *Mixed Numbers and Fractions Greater Than One*. Standard: `4.NR.2.5`.

**Concept → action → result → reasoning:** Fractions greater than one and mixed numbers name the same amount; bundle/unbundle equal parts; see unchanged filled area and position; explain the whole groups and remaining pieces.

**Practice setup:** Thirteen quarter-size tiles and four equal-size frames, each holding four quarters. The learner first commits “between 2 and 3 / 3 and 4 / 4 and 5 wholes.” No mixed-number answer is displayed initially.

**Loop:** Fill whole frames → count whole groups and leftover fourths → enter both representations → switch to an independent reverse round, `2 3/4`, and unbundle the wholes into fourths → compare the unchanged area in each round. Large “Make a whole” and “Break one whole into fourths” controls complement individual tile placement. A number line follows the learner-built amount without printing the answer before entry.

**Dialogue:** Nutty: “A whole can be packed with four fourths. Let’s see two ways to name the same pile.” Kid: “I’ll bundle the pieces into wholes, then unpack another mixed number to check the connection.” Start: **Bundle the pieces**.

**Coaching:** Treating leftover count as denominator: “How many equal pieces fill one whole?” First equivalence: “The pieces stayed the same. Only their grouping changed.” Reverse-round mistake: “Count the fourths inside every whole before adding the loose pieces.” Completion: “You renamed both quantities without adding or losing any fourths.”

**Finish/key:** 13/4 = 3 1/4 and 2 3/4 = 11/4. Require both directions and an explanation linking four fourths to one whole. A prediction mismatch invites comparison, not a failure score.

**Build/verify:** Share the extended multiwhole fraction engine with M4; distinct conversion task. Test same-size wholes, remainder bounds, both directions, and no auto-answer labels.

## M6 — Decimal Exchange Mat

**Placement:** `math-u08-l03-c3` in `math-u08-l03`, *Add and Subtract Tenths and Hundredths*. Standard: `4.PAFR.2.2`.

**Concept → action → result → reasoning:** Add/subtract matching place values through equal-value exchanges; manipulate whole, tenth, and hundredth pieces; compare fraction and decimal records; explain why exchanging preserves quantity.

**Practice setup:** Round A: `0.48 + 0.36`. Round B: `1.2 − 0.35`. Show unit-square mats divided into hundredths, tenth strips spanning ten cells, and whole tiles covering a full mat. Printed fractions accompany each piece size; integer hundredth counts drive the model.

**Loop:** Estimate each answer's size → build the two addends and exchange ten hundredths for one tenth → record 84/100 and 0.84 → start Round B with one whole and two tenths → rename a whole and a tenth as needed, remove the subtrahend, and record the difference. The learner confirms the result before the equality is printed; no score is tied to the prediction.

**Dialogue:** Nutty: “Our pieces can trade places without changing their value. That can help us add and subtract.” Kid: “I’ll match the piece sizes, make equal trades, and write each result as a fraction and a decimal.” Start: **Open the exchange mat**.

**Coaching:** Invalid exchange: “An exchange needs ten smaller pieces for one piece in the next place.” Removal failure: “Rename a larger piece so you have the parts you need to remove.” After a valid construction: “Count the value left on the mat, not just the number of pieces.” Completion: “Your fraction and decimal records describe the same remaining or combined amount.”

**Finish/key:** A: 84/100 = 0.84. B: 120/100 − 35/100 = 85/100 = 0.85. Require correct model, record, and equal-value explanation in both rounds.

**Build/verify:** New decimal mode using regrouping/fraction patterns. Do not push denominators of 100 through the existing ≤12 fraction schema. Test exact hundredth arithmetic, crossing a whole, and invalid partial exchanges.

## M7 — Weigh the Field Kit

**Placement:** `math-u09-l04-c3` in `math-u09-l04`, *Measure Customary and Metric Weight*. Standard: `4.MGSR.2.4`.

**Concept → action → result → reasoning:** Read a scale in a named unit and round to a whole unit; place an object, set a reading marker, and choose neighboring whole numbers; retain the scale reading and rounded record; explain the halfway comparison.

**Practice setup:** Four supplied scale situations: apple on an ounce scale, 5.6 oz; backpack on a pound scale, 7.3 lb; eraser on a gram scale, 23.4 g; camping kit on a kilogram scale, 3.5 kg. These are authored measurement models, not measurements of the learner's objects. Each instrument prominently names its unit; the task does not require conversions between systems.

**Loop:** Pick a kit object and predict which of two shown units gives a more convenient-sized reading → place it on its labeled scale → align a large keyboard-operable marker with the needle → record the neighboring whole units and select the nearer → keep a four-row field notebook. If the initial unit choice is less convenient, explain scale readability without saying another legitimate unit is mathematically impossible.

**Dialogue:** Nutty: “The kit has light and heavy objects. Let’s read each scale carefully and keep its unit.” Kid: “I’ll place each object, find the neighboring whole numbers, and record the nearest one.” Start: **Weigh the kit**.

**Coaching:** Missing unit: “Keep the scale's unit with your number.” Rounding error: “Compare the needle with the halfway point between those two whole marks.” First record: “Your notebook keeps both the reading and the rounded value.” Completion: “You read four scales and kept the units with your measurements.”

**Finish/key:** 6 oz, 7 lb, 23 g, 4 kg; explicit half-up treatment of 3.5. Require all four records and a nearer/halfway explanation. Unit preference is formative guidance, not an exclusive scientific truth.

**Build/verify:** New scale-reading activity, not the existing equality balance. Needle, tick marks, and accessible reading text use one value source. Test exact halfway, all four units, accessible nonvisual readings, and mobile marker controls.

## M8 — Fence the Garden

**Placement:** `math-u10-l01-c2` in `math-u10-l01`, *Rectangle Perimeter and Unknown Sides*. Standard: `4.MGSR.1.1`.

**Concept → action → result → reasoning:** Perimeter includes both pairs of opposite sides; allocate a fixed fence length around a rectangle; observe covered boundary and remaining fence; infer and verify an unknown side.

**Practice setup:** A rectangle has perimeter 34 m and length 11 m. Width is unknown. A fence reel holds 34 one-meter segments. Learners assign the known opposite pair first, then split the remaining fence equally between the other pair.

**Loop:** Predict whether subtracting one length is enough → place 11m on each long side → split the remaining 12m into two equal sides → set the width and submit → compare the completed shape and four-side sum. A brief transfer round gives length 7m and width 4m and asks for the fence total. The diagram scales to the entered dimensions; its edges, not interior tiles, show fence use.

**Dialogue:** Nutty: “This fence must go around every edge of the garden. Two side lengths are missing.” Kid: “I’ll use fence for both known sides, share what remains, and check all four edges.” Start: **Fence the garden**.

**Coaching:** One length subtracted: “Find the opposite side with the same length. It needs fence too.” Unequal remaining sides: “What must be true about opposite sides of a rectangle?” Valid allocation: “Read all four side labels to check your boundary.” Completion: “Your fence covers the complete boundary with equal opposite sides.”

**Finish/key:** Unknown width 6m; 11 + 6 + 11 + 6 = 34. Transfer: 22m. Require the allocation and a complete perimeter equation, not just entering six. No square units accepted for perimeter.

**Build/verify:** New perimeter task. Reuse geometric drawing utilities only. Test opposite-side equality, one-edge omission, sum conservation, and visually proportional rectangles.

## M9 — Triangle Inspection Desk

**Placement:** `math-u11-l01-c3` in `math-u11-l01`, *Classify Triangles by Sides and Angles*. Standard: `4.MGSR.3.1`.

**Concept → action → result → reasoning:** Classify the same triangle in two ways using measurements; rotate/inspect triangles and attach category labels; see a dual classification record; cite the marks that support each name.

**Practice setup:** Four cards with neutral names A–D and deliberately varied orientation. A has three equal sides and angles 60°,60°,60°. B has exactly two equal sides and 45°,45°,90°. C has three unequal sides and 30°,40°,110°. D has exactly two equal sides and 40°,70°,70°. Geometry must be derived from those angles; side marks match actual equalities. Class names never appear in initial shape titles or alternative text.

**Loop:** Inspect side marks/angle labels → place each triangle into its side category and all applicable angle categories → submit → choose the evidence marks supporting one repaired classification → rotate the shape and confirm its classifications stay the same. Accessible descriptions give the measurements, not an answer key.

**Dialogue:** Nutty: “A triangle can have a side name and an angle name. Turning it won't change its measurements.” Kid: “I’ll inspect the marks, give both kinds of names, and show my evidence.” Start: **Inspect the triangles**.

**Coaching:** Appearance-based error: “Use the printed measurements and matching marks, even when the triangle is tilted.” Missing second label on A: “Check both whether every angle is less than ninety and whether all angles are equal.” Valid classifications: “Point to the marks that support your names.” Completion: “You used side and angle evidence, and rotation kept both classifications unchanged.”

**Finish/key:** A equilateral, acute, equiangular; B isosceles, right; C scalene, obtuse; D isosceles, acute. Preserve this lesson's exactly-two-equal-sides definition of isosceles. Require all memberships and the evidence check.

**Build/verify:** Extend existing shape classifier classification mode with evidence/rotation if missing. Existing schema supports these memberships. Test equiangular plus acute, no leaked class names, and exact rendered geometry.

## M10 — Graph Detective

**Placement:** `math-u12-l02-c3` in `math-u12-l02`, *Solve Problems with Graphs and Tables*. Standard: `4.DPSR.1.2`.

**Concept → action → result → reasoning:** Translate a graph's marks into quantities before choosing one operation; inspect keys and highlight relevant data; retain a linked equation and answer; explain why the operation answers the question.

**Practice setup:** Three short cases. Picture graph: key one basket = 4 apples; Trail Group has 2½ basket symbols; ask how many apples it picked. Bar graph: bird observations Robin 18 and Wren 11, with a labeled scale; ask how many more robins. Fraction table: two ribbon lengths 3/8 m and 4/8 m; ask combined length. Whole and half symbols have matching text equivalents; labels identify what is being counted.

**Loop:** Read key/units → mark the relevant symbols, bars, or rows → build one operation from those values → submit the result with its unit → explain what the key or question changed about the calculation. Enlarging a symbol shows four countable apples; a half symbol shows two. The learner can split the two complete basket symbols into halves, producing five equal half-basket symbols for a one-step multiplication. The full dataset and key remain available throughout.

**Dialogue:** Nutty: “A picture can stand for more than one thing. Check the key before choosing a calculation.” Kid: “I’ll read the display, mark the data I need, and build one equation for each question.” Start: **Inspect the data**.

**Coaching:** Raw symbol counting: “How many apples does one complete basket stand for?” Wrong operation: “Is the question asking for a total or a difference?” Fraction error: “Keep eighth-size pieces as eighths when you combine them.” Completion: “You used the display's key, values, and units to answer each question.”

**Finish/key:** 5×2 = 10 apples using the five half-basket symbols; 18−11 = 7 birds; 3/8 + 4/8 = 7/8 m. For the picture case, splitting symbols preserves the same pictured data and avoids requiring decimal multiplication or a multistep equation. Require relevant data, supported operation, result, and unit in all three cases.

**Build/verify:** Extend data-plot family with read/solve displays or add a focused reader. Existing bar-building configuration does not alone supply picture keys and fraction-table reasoning. Test half-symbol scale, fractional unit preservation, and choice of operation.
